# Cabinet Capacity 50/20 Review

结论：源码证据支持“逐零件初始化没有恢复安装设备容量 profile”的修复方向；隔离候选已通过静态和 Lua 测试，但尚未达到游戏内验收标准。

## 修复要求

1. 保留现有 `VLS.Damage.Init(vehicle)` 的车辆级初始化语义。
2. 为生活槽提供逐零件的初始化入口，并在恢复 profile 前校验 vehicle、part、part id 和 universal-part 身份。
3. 只重定向生活槽的 16 个 `init` 绑定；屋顶行李架等其他用途不得被泛化修改。
4. 合法访问兜底必须位于既有存储、角色、车辆和零件身份检查之后。
5. 不替换容器、不关闭 `hasRoomFor`、不把所有默认容量从 20 改成 50、不扫描所有车辆、不加入存档迁移。

## 验收要求

- 原版 Van、StepVan、KI5 房车的不同 profile 容量分别正确恢复。
- 显示容量和实际可转移容量一致。
- 安装、拆卸、保存、重连和首次操作均不回退到旧容量。
- 未授权角色或错误车辆/零件身份仍被拒绝。
- 家电状态、物品身份、容器内容和其他屋顶功能不回归。
- 必须保留游戏内证据；离线测试只能标记为 `verified-offline`。

## 当前判断

候选满足源码层面的最小修复约束，暂不把它标记为 `accepted`。下一位 Agent 的第一步是读取任务和全部证据，核对当前 Git/source/runtime，再在隔离测试环境复现真实容量和转移行为。
